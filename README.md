# Replication materials: Ranked but Not Graded: What Selective Verification Establishes About Deployed Detectors

This repository holds the simulation code, the frozen simulation outputs, and the
arithmetic verification scripts behind the article named above. Every simulation figure
quoted in the article and its supplementary material is read from `sim/results.json` and
`sim/gate.json`; nothing is typed in by hand.

## Layout

```
sim/dgp.py          data-generating process and closed forms (constants, thresholds,
                    population realization, pairwise cell tables)
sim/exact.py        exact finite-population conditional test (hypergeometric, clipped
                    composite-null boundary, any integer margin)
sim/run.py          the sequential experiment: 48 cells x 2,000 replicates, seven
                    procedures, two challenger policies; writes sim/results.json
sim/gate.py         implementation gate: exact flag-count checks and z-scored moment
                    checks against the closed forms; writes sim/gate.json
sim/analyse.py      reads sim/results.json and prints the gate summary, the five
                    falsification criteria in their declared order, and the headline
                    operating figures
sim/results.json    frozen output of sim/run.py (the reported run)
sim/gate.json       frozen output of sim/gate.py (the reported gate)
checks/*.py         five standalone arithmetic verification scripts; each records the
                    quantities it prints as assertions and exits non-zero on failure
Makefile            `make gate`, `make checks`, `make analyse`, `make simulate`
```

All paths are relative to the repository root; run everything from there.

## Requirements

Python 3.14 with NumPy 2.4, SciPy 1.17 and SymPy 1.14 (the versions the frozen outputs
were produced with; nearby versions are expected to work). Install with

```
python3 -m pip install numpy scipy sympy
```

## What each command regenerates

```
make gate       # python3 sim/gate.py
```
Realizes the twelve (prevalence, flag rate, correlation) populations from the frozen
seed, runs the seventy checks per population, prints PASS or FAIL, and rewrites
`sim/gate.json`. The rewritten file is expected to be identical to the frozen one; the
gate is deterministic.

```
make checks     # python3 checks/<each>.py
```
Runs the five verification scripts. They use exact rational or symbolic arithmetic, have
no random draws and no free parameters, and confirm the arithmetic of the article's
stated identities: the contrast cancellation, the verification-support bounds on
hand-written populations, the relative-efficiency bound on a fixed grid, the
minimality witness for the centered family, and the reference-standard reversal
identity with matched flag volume. Each exits 0 on success.

```
make analyse    # python3 sim/analyse.py
```
Prints every reported simulation figure from `sim/results.json`.

```
make simulate   # python3 sim/run.py   -- long; overwrites sim/results.json
```
Reruns the full experiment from the frozen seed sequence (entropy `20260823` in
`sim/dgp.py`); about six minutes on a laptop. The run is exactly reproducible: with the
pinned NumPy and SciPy versions it regenerates `sim/results.json` byte-for-byte,

```
SHA-256  sim/results.json  85c01782f11dc922a2856e86a934d812de63fa702d83eba9405f0ecf99a0d766
SHA-256  sim/gate.json     c2b75e7d8a6ad4c4a6a08afd8263ccbbc590fe6e1783ca98c5d8fe1bc6112f50
```

Copy the frozen file aside before running if you want to diff.

### How each arm's random stream is chosen

Each cell spawns 64 child seeds, and each of the fourteen arms (seven procedures by two
challenger policies) draws its verification samples, challenger choices and adjudication
errors from one of them. The code that produced the reported run selected the child for
an arm through Python's built-in string hashing, which is randomized per process, so the
assignment of arms to streams varied from one run to the next and the reported file could
not be regenerated by rerunning. The assignment the reported run actually used was
recovered from the frozen output, by trying each of the 64 children against cell 0 and
then confirming that the recovered assignment regenerates all 48 cells byte-for-byte, and
it is now pinned as the explicit table `STREAM_INDEX` in `sim/run.py`. One consequence of
the original selection is visible in that table: two arms, `controlled|random` and
`oracle|random`, drew from the same stream (index 55). No reported figure compares those
two arms as independent draws; the comparison between them in the article is of levels.

## Design constants

Population size 10^6, twenty methods on a fixed signal ladder, prevalence in
{0.001, 0.01}, flag rate in {0.001, 0.005}, score correlation in {0.3, 0.6, 0.9}, two
margins, two per-round budgets, horizon 20 rounds, alpha = 0.05 spent as alpha/20 per
round. Flagging is top-k by score at k = floor(q N), which makes matched flag volume hold
exactly in every realized population; verification is drawn only from the cells where
the incumbent and challenger disagree. The constants are defined once, in `sim/dgp.py`.
